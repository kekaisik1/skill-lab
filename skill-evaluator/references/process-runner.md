# Authored subprocess runner

`python3 scripts/fixture_runner.py positive --out <new-directory>` runs only named bundled fixtures. The runner has no arbitrary-source or model adapter. Bubblewrap must work; preflight failure is infrastructure_error, never a pass. In this environment the outer sandbox blocks namespace initialization; use the supported approval route for the exact runner invocation. Do not remove isolation flags to make a failed probe run.

The controller executes an authored candidate Python process that writes `solution.py`. After that namespace exits, it rejects missing/symlink/oversized artifacts, freezes an evaluator-owned copy and tests that copy in separate namespaces. Inputs arrive on stdin; expected outputs and oracle code never enter the candidate filesystem. Correctness comes from controller comparisons, not candidate stdout claims. Runtime-private checks remain in a controller-only temporary directory. Current checks are public regression cases embedded in the trusted runner, so this demonstrates access isolation, not scientifically unseen evaluation.

Mounts are read-only `/usr`, `/lib`, `/lib64`, a single candidate script, and a writable scratch output mount for generation. Home, projects, credentials and the host temporary directory are absent. Grading mounts only the frozen script and empty scratch space. `--unshare-all`, capability dropping, empty environment, isolated network/PID/user/mount namespaces and die-with-parent are enforced by installed bubblewrap. `/usr` is a broad system-runtime mount, not a minimal dependency image. No defense against kernel vulnerabilities is claimed.

Limits: 2 seconds wall time per subprocess, 1 CPU second, 256 MiB address space, 16 KiB combined captured output, 64 KiB per created file, 64 file descriptors, process-count rlimit 256 applied after namespace creation. These are per process/file limits, not aggregate memory, CPU or disk quotas. The authored allowlist is therefore a hard scope restriction; arbitrary hostile repositories remain unsupported. Network namespace isolation does not enable external network access.

The controller kills the process group in a finally block and reaps the leader; killing the namespace init terminates namespace descendants. Tests cover child delayed side effects after timeout and KeyboardInterrupt. Temporary workspaces are removed by the context manager. Receipts and frozen solution artifacts remain for inspection. A hard controller SIGKILL could leave a temporary directory; die-with-parent still constrains its child, but reboot/crash cleanup is not implemented.

Statuses separate valid pass/fail from invalid artifact/protocol, candidate timeout/output/process errors, grading timeout/process errors, isolation failure, preflight infrastructure failure, and controller/grader exceptions. An isolation failure cannot earn a pass. Actual process commands, PIDs, exits, capped output, elapsed time, source/artifact/oracle/runtime hashes and cleanup handling are recorded. Receipts are controller-authored, but not cryptographically authenticated; imported records still cannot certify performance. Crashes and invalid protocol are conservatively inconclusive/invalid, not silently counted as ordinary wrong answers.
